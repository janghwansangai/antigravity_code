# 🌱 나의 포트폴리오 만들기

학생이 1년 동안의 **🎨 작품 사진 · 📸 활동 사진 · 🎬 동영상 · 📄 PDF**를 올리고 글을 쓰면, 휴대폰과 컴퓨터에서 예쁘게 보이는 포트폴리오를 **웹페이지 파일(.html) · 압축 파일(.zip) · PDF**로 만들어 주는 웹앱입니다.

- 초등학생도 혼자 쓸 수 있게 **3단계**(① 내 소개 → ② 활동 기록 → ③ 꾸미기·저장)로 단순하게
- 디자인 **15종**: 귀여운 디자인 6종 + 깔끔한 디자인 9종, 누르면 바로 미리보기
- 사진 **돌리기 · 자르기 · 얼굴 가리기**(모자이크·스티커), 가로/세로 사진에 맞춘 **자동 배치** 또는 **가로 N장 격자**
- **📷 카메라로 바로 찍기**와 **📄 문서 스캔**(모서리 자동 찾기 → 반듯하게 → 그림자 지우기), **캡처 화면 붙여넣기**(Ctrl+V)
- **PDF 내용이 보이게** 올리기(2×2, 3×3 등 쪽 배치), **동영상** 올리기(PDF로 저장할 땐 썸네일만)
- **사진·동영상 용량 자동 줄이기**: 휴대폰 사진 5MB → 약 0.4~0.6MB, 1080p 동영상 1분 약 120MB → 약 11MB(720p MP4) · 약 6MB(480p)
- **🌈 우리 반 갤러리**: ③단계의 **🚀 갤러리에 공유하기** 한 번이면 가벼운 PDF(또는 웹페이지)가 선생님 구글 드라이브에 저장되고 학급 갤러리에 표지 그림과 함께 올라감 · PDF·ZIP·웹페이지는 갤러리에서 바로 보기
- 파일 크기 제한 없이(한 파일 1GB까지) 올리고, **프로젝트 파일(.portfolio)** 로 이 컴퓨터에 저장·열기
- **서버가 없습니다.** 모든 작업은 학생 각자의 브라우저에서 처리·저장되므로 반 전체가 동시에 써도 서버 부하가 없습니다.

## 👩‍🏫 선생님: 학생들에게 나눠 주는 방법

| 방법 | 하는 법 | 이럴 때 |
| --- | --- | --- |
| **① 파일 하나 나눠 주기** (가장 쉬움) | [`student_portfolio_webapp.html`](./student_portfolio_webapp.html) 파일을 학생에게 보내고 두 번 눌러 열게 합니다. 설치·인터넷 필요 없음(글꼴만 인터넷이 있으면 더 예뻐짐). | 컴퓨터실, 태블릿에 파일 복사 |
| **② 웹 주소로 열기** | Cloudflare Pages에 배포한 주소를 알려 줍니다(아래 ‘배포’ 참고). | 각자 기기(크롬북·태블릿·집 컴퓨터) |

> 학생 작업은 **그 기기의 브라우저 저장 공간(컴퓨터 디스크)에 자동 저장**됩니다. 사이트를 업데이트해도 지워지지 않습니다. 다른 기기에서 이어서 하거나 학교 공용 컴퓨터를 쓴다면 ③단계의 **‘프로젝트 파일 저장’**(.portfolio)을 꼭 챙기게 해 주세요. 시크릿(사생활 보호) 창에서는 창을 닫으면 지워집니다.

### 학생이 제출하는 것
- **🌐 웹페이지 파일(.html)** — 파일 하나에 사진·PDF·동영상이 들어 있어 제출·공유가 가장 쉽습니다. 휴대폰에서도 열립니다. (15MB 넘는 동영상·파일은 휴대폰에서도 열리도록 썸네일·안내만 넣고, 원본은 ZIP에 들어갑니다. 동영상을 720p로 줄여 두면 1분짜리도 들어갑니다)
- **🖨️ PDF** — A4 문서. 인쇄 창에서 ‘PDF로 저장’. 동영상은 썸네일 그림, PDF 자료는 고른 쪽 그림이 들어갑니다.
- **📦 ZIP** — `index.html` + `assets/photos/` · `videos/` · `files/` · `pages/` (모든 원본 포함)
- **💾 프로젝트 파일(.portfolio)** — 다시 편집하기 위한 파일(사진·동영상·PDF 원본 포함). 다른 컴퓨터에서 ‘프로젝트 파일 열기’로 이어서 합니다.

### 🌈 우리 반 갤러리 (버튼 하나로 공유 · 구글 드라이브에 모으기)

학생이 포트폴리오 앱 ③단계에서 **🚀 갤러리에 공유하기**를 누르면, 작품이 **선생님 구글 드라이브의 작품 폴더**에 저장되고 **우리 반 갤러리에 카드로 바로 올라갑니다.** 링크를 복사해 붙여 넣을 필요가 없습니다(드라이브 링크는 자동으로 복사돼 클래스룸 등에 따로 낼 때 씀). 다시 공유하면 전에 올린 것을 새것으로 바꿉니다. 목록은 **선생님의 구글 시트**에 쌓입니다(서버·비용 없음).

| 공유 형식 | 내용 | 크기·속도(시험) |
| --- | --- | --- |
| **📄 PDF (추천)** | 앱이 A4 PDF를 바로 만듦: 표지(대표 사진·소개·차례) + 활동마다 사진 격자·글·배우고 느낀 점·PDF 자료 쪽. 동영상은 ▶ 썸네일. 고른 디자인의 색을 씀 | 사진 4장(21MB)+동영상(30MB) → **0.54MB**, 갤러리에서 **0.2초** 만에 열림 |
| **🌐 웹페이지** | 고른 디자인 그대로(분류 버튼·사진 크게 보기·동영상 재생). 사진은 긴 변 1280px, 10MB 넘는 동영상·5MB 넘는 첨부파일은 썸네일·안내로 바꿈 | 같은 자료 → **1.5MB**, 갤러리에서 **0.6초** |

- 갤러리 카드에는 **표지 그림(썸네일)** 이 보입니다(대표 사진, 사진이 없으면 제목 카드).
- 갤러리의 **＋ 내 작품 올리기**에서도 **📁 파일 올리기**(PDF·ZIP·HTML·사진·동영상, 100MB까지, 큰 파일은 4MB씩 나눠 올림) 또는 **🔗 드라이브 링크**로 올릴 수 있습니다.
- 학생 앱에는 ‘갤러리 만들기’가 보이지 않습니다. 학생은 선생님이 알려 준 **갤러리 주소를 붙여 넣거나 QR로 한 번 열면** 연결됩니다. `gallery.html` 설정 화면 맨 위에는 “학생이에요? 여기서는 아무것도 하지 않아도 돼요” 안내가 있고, 이 화면에서 버튼을 눌러도 아무것도 만들어지지 않습니다(갤러리는 선생님이 구글 시트·Apps Script로 직접 만들어야 생김).

**선생님 준비 (10분, 한 번만)** — 배포한 사이트의 `gallery.html`을 열면 같은 안내가 나옵니다.
1. 새 구글 시트 만들기 → **확장 프로그램 → Apps Script**
2. [`apps-script/Code.gs`](./apps-script/Code.gs) 코드를 붙여 넣고 저장 (갤러리 화면의 ‘📋 코드 복사’ 버튼)
3. 위쪽 함수 목록에서 **‘준비하기’ → ▶ 실행 → 권한 허용** (드라이브에 ‘우리 반 갤러리 작품’ 폴더가 만들어짐)
4. **배포 → 새 배포 → 웹 앱**, 실행 사용자 **나**, 액세스 **모든 사용자** → 웹 앱 URL 복사
   - 학교 계정에서 ‘모든 사용자’가 안 보이면 관리자가 막아 둔 것이라 개인 구글 계정으로 만듭니다.
5. `gallery.html`에 URL을 붙여 넣고 ‘연결 확인’ → 나오는 **갤러리 주소·QR**을 학생에게 알려 주기

> **이미 갤러리를 만든 선생님(예전 코드)**: 새 `Code.gs`로 바꿔 붙여 넣고 저장 → ‘준비하기’ ▶ 실행(권한 허용) → **배포 → 배포 관리 → ✏️ 수정 → 버전: 새 버전 → 배포**. 갤러리 주소는 그대로이고 이미 올라온 작품도 그대로입니다. 예전 코드인 동안에는 갤러리 위에 ‘선생님께: 새 버전으로’ 안내가 보이고, 학생은 링크 올리기만 할 수 있습니다.

**시트에서 관리하기**: ‘설정’ 탭에서 갤러리 제목 · **학급 코드**(적으면 코드를 아는 학생만 올림) · 올리기 허용(FALSE면 닫힘) · **작품 폴더**(학생 파일을 저장할 드라이브 폴더 주소, 학생들과 함께 쓰는 폴더를 넣어도 됨, 비우면 자동 폴더). ‘작품’ 탭에서 줄을 지우거나 ‘숨김’ 칸에 TRUE를 적으면 갤러리에서 사라집니다(목록은 최대 20초 뒤, 📖 보기는 바로 막힘).

- 올린 파일은 ‘링크가 있는 사람 보기’로 공유합니다. 학교 계정이라 막혀 있으면 ‘링크가 있는 우리 학교 사용자’로, 그것도 막혀 있으면 공유 없이 저장하고 갤러리에서만 볼 수 있습니다.
- 학생이 다시 공유해 ‘바꾸기’를 하면, 예전에 앱으로 올렸던 파일은 드라이브 휴지통으로 갑니다. 갤러리에서 ‘지우기’를 하면 카드만 지우고 드라이브 파일은 그대로 둡니다.

**📖 보기 (PDF·ZIP·웹페이지를 갤러리 안에서 바로)**
구글 드라이브는 웹페이지(.html)를 열어 주지 않고 ZIP도 풀어 주지 않습니다. 그래서 갤러리가 선생님 Apps Script를 통해 파일을 받아 **브라우저 안에서 풀어** 보여 줍니다(ZIP은 풀지 말고 그대로 올리면 됨).
- 되는 파일: **PDF**(40MB까지, 앱에서 만든 PDF는 pdf.js 없이 바로), **ZIP**(이 앱의 ZIP, 또는 학생이 직접 만든 `index.html` + 사진·CSS·JS 묶음), **웹페이지 파일(.html)**, **프로젝트 파일(.portfolio)** · 200MB까지
- 빠르게: 4MB 조각을 **2개씩 동시에** 받고 실패한 조각은 다시 받습니다. 한 번 본 작품은 그 기기에 기억해 두어(최근 8개) **다시 열면 바로** 열립니다. 갤러리에서 오래 걸리는 것은 대부분 큰 파일이므로 **🚀 공유하기(가볍게 만들어 올림)** 를 쓰는 것이 가장 빠릅니다.
- 학생 웹페이지는 갤러리와 분리된 **샌드박스**에서 열려 다른 학생 기록·저장소에 접근할 수 없습니다.
- 갤러리에 올라온(숨기지 않은) 작품의 파일만 읽습니다. 사진·동영상·구글 문서·유튜브 링크는 카드에서 미리보기로 열립니다.

### 배포 (Cloudflare · GitHub 연결)

Cloudflare 대시보드 → **Workers & Pages** → 만들기 → Git 저장소 가져오기 → `janghwansangai/antigravity_code`

- **Workers로 만든 경우**(배포 명령 `npx wrangler deploy` 칸이 있는 화면): 저장소의 `wrangler.jsonc`가 빌드와 `dist/` 업로드를 처리하므로 기본값 그대로 두면 됩니다. 주소는 `https://<이름>.<계정>.workers.dev`
- **Pages로 만든 경우**: 아래 값을 입력합니다. 주소는 `https://<이름>.pages.dev`

| 설정 | 값 |
| --- | --- |
| 프로덕션 브랜치 | `main` |
| 프레임워크 | 없음(None) |
| 빌드 명령 | `npm run build` |
| 빌드 출력 디렉터리 | `dist` |

- 이후 `main`에 push하면 자동으로 다시 배포되고, 다른 브랜치는 미리보기 주소가 따로 생깁니다.
- Node 버전은 `.node-version`(22), 캐시·보안 헤더는 `public/_headers`에 있습니다.
- ⚠️ **사이트 주소(도메인)는 한 번 정하면 바꾸지 마세요.** 학생 작업은 브라우저에 주소별로 저장되어, 주소가 바뀌면 백업 파일로 옮겨야 합니다. 개인 도메인을 쓸 계획이면 학생들이 쓰기 전에 연결하세요.

## 🧒 학생 화면 한눈에

1. **내 소개** — 이름, 학교, 제목, 소개글 (표지에 들어감)
2. **활동 기록** — `＋ 새 활동`, `🖼️ 사진부터 올리기`, `📷 카메라로 찍기`, `📄 문서 스캔`, `📋 캡처 붙여넣기`
   - 업로드 칸 4개: **🎨 작품 사진 / 📸 활동 사진 / 🎬 동영상 / 📄 PDF·파일** (눌러서 고르기 · 끌어다 놓기 · Ctrl+V 붙여넣기)
   - **캡처 붙여넣기**: 화면을 캡처(윈도우 Win+Shift+S, 맥 ⌘+Ctrl+Shift+4)한 뒤 **어느 화면에서든** Ctrl+V(⌘+V). 활동을 편집 중이면 그 활동에, 아니면 새 활동이 만들어집니다.
   - **사진 화질**: 작게(1280px) · 보통(1600px, 기본) · 크게(2400px). 휴대폰 사진(수 MB)은 자동으로 줄여 저장합니다.
   - **사진 배치**: 자동 맞춤(가로/세로 비율대로 꽉 채움) 또는 **가로 2·3·4장씩**(모든 칸이 같은 크기, 마지막 줄도 같은 크기)
   - 사진마다 설명, `⇄` 작품↔활동 바꾸기, `☆ 대표로`, `↻` 돌리기, `✂️` 자르기(자유·1:1·4:3·3:4·16:9), `✏️ 고치기`(자르기 · 문서 스캔 · 모자이크 · 스티커 · 되돌리기)
     - 저장하면 원래 사진은 저장소에서 지워지고 고친 사진만 남습니다(내보낸 파일에도 고친 사진만 들어감)
   - **카메라**: 📷 사진 모드는 여러 장 연속 촬영, 📄 문서 모드는 찍은 뒤 모서리 자동 찾기 → 반듯하게 펴기 → 선명한 색/흑백 문서. 카메라를 못 쓰는 기기는 기본 카메라·파일 선택으로 대신합니다.
   - **동영상**: 1GB까지 올리고 썸네일을 자동으로 만듭니다. 포트폴리오에서는 재생, PDF에는 썸네일만.
     - **동영상 크기**(올릴 때 자동으로 줄임): **보통 720p**(기본, 1분 약 12MB) · **작게 480p**(1분 약 6MB) · 원본 그대로. 어느 기기에서나 재생되는 **MP4**로 바꾸고, 60fps는 30fps로 줄입니다. 이미 작은 동영상은 그대로 둡니다.
     - 시험 결과(휴대폰 촬영과 같은 1080p·16Mbps, 20초): 41.7MB → **3.7MB**(720p) · **1.9MB**(480p) / 세로 1080×1920·60fps 8초: 20.8MB → **1.5MB**
     - 크롬·엣지·웨일·최신 사파리(16.4+)·파이어폭스(130+)에서 됩니다. 안 되는 브라우저나 이 기기가 풀 수 없는 형식(예: 일부 아이폰 HEVC)은 원본을 그대로 저장합니다.
   - **PDF**: 쪽을 그림으로 만들어 **내용이 보이게** 넣습니다. ‘첫 쪽만 · 2쪽 · 2×2 · 3×2 · 3×3 · 모든 쪽(가로 2·3장)’ 중 고르고, 쪽을 눌러 넣거나 뺄 수 있습니다(최대 60쪽까지 그림으로 만듦). 원본은 ‘열어 보기’ 카드로도 남습니다.
3. **꾸미기·저장** — 디자인 15종 중 고르기 → 웹페이지/PDF/ZIP 저장, **프로젝트 파일 저장·열기**, **🌈 우리 반 갤러리**, **저장 공간 확인 · 🗜️ 사진 / 🎬 동영상 용량 줄이기**(이미 올린 것도 줄임)
   - 프로젝트 파일: 크롬·엣지(컴퓨터)에서는 처음 저장한 파일을 기억해 다음부터 ‘저장’만 누르면 같은 파일에 덮어씁니다. 다른 브라우저는 내려받기 폴더에 저장됩니다.

상단 **이름표(🙂 이름 ▾)** 를 누르면 한 컴퓨터를 여러 학생이 쓸 때 **내 포트폴리오를 골라 이어서** 하거나 **새 친구 포트폴리오**를 만들 수 있습니다(서로 덮어쓰지 않음).

## 🚦 여러 학생 동시 사용 · 사진 대량 업로드 점검 결과

서버는 처음 한 번 **앱 파일(약 230KB, 압축 시 약 75KB)만** 보내고, 사진·PDF는 서버로 올라가지 않습니다. 그래서 학생 수가 늘어도 서버 부담이 거의 없습니다.

테스트 환경: CPU 4개 리눅스 컴퓨터 1대, 헤드리스 크롬, 5MB짜리 휴대폰 크기 사진(4032×3024).

| 항목 | 결과 |
| --- | --- |
| 정적 서버: 학생 300명이 동시 100명씩 첫 화면 요청 | 1.2초, 실패 0건 |
| 독립된 브라우저 20명 / 30명이 동시에 사진 6장+PDF 업로드 → 내보내기 → 새로고침 | 20/20, 30/30 성공, 학생 간 데이터 섞임 없음 |
| 학생 1명 첫 화면 | 약 0.3초 (구글 글꼴이 막힌 학교망에서도 0.2초) |
| 5MB 사진 1장 저장 크기 | 약 0.5MB로 자동 축소 |

**한 학생이 사진을 많이 올렸을 때 — 기존 버전과 비교**

| 사진 수 | 항목 | 기존 버전 | 새 버전 |
| --- | --- | --- | --- |
| 12장 | 글자 입력 → 미리보기 반영 | 5.0초 | 0.17초 |
| 12장 | 글자 입력 때마다 다시 저장하는 크기 | 80MB | 0.7MB |
| 12장 | 새로고침 후 복원 | 3.5초 | 0.3초 |
| 60장 | 동작 여부 | ❌ 메모리 1.6GB, `Invalid string length` 오류로 미리보기 멈춤 | ✅ 입력 반영 0.18초, 새로고침 0.4초, 웹페이지 1파일 저장 1.1초(47MB) |

개선 내용: 사진 자동 축소, 사진·동영상·PDF는 파일(Blob) 그대로 따로 한 번만 저장(글을 고칠 때는 글만 저장), 화면에는 짧은 `blob:` 주소 사용, 같은 사진은 페이지에 한 번만 넣음, PDF 처리 코드는 PDF를 올릴 때만 불러옴, 저장 공간 부족 시 안내, 같은 포트폴리오를 두 창에서 고치면 경고, 업로드 칸 밖에 파일을 떨어뜨려도 페이지가 바뀌지 않도록 보호.

**🚀 갤러리에 공유하기** (같은 흉내 환경): PDF 공유 0.5초 · 다시 공유하면 같은 카드가 바뀌고 예전 파일은 휴지통 · 26MB 파일을 4MB씩 7번 나눠 올려 원본과 바이트까지 같음 · 10명 동시 파일 올리기 성공 · 학교 계정 공유 제한·예전 버전 서버에서도 안내와 함께 동작.

**🌈 갤러리** (실제 `Code.gs`를 구글 시트·드라이브 흉내 환경에서 실행해 시험): 30명이 동시에 링크 올리기 30/30 성공 · 수식(`=HYPERLINK(…)`)·날짜처럼 보이는 제목(`6/12`)도 글자 그대로 저장 · 숨긴 작품과 갤러리에 없는 드라이브 파일은 읽기 거절 · 📖 61MB ZIP(동영상·PDF 포함) 펼치기 약 8초(대부분 내려받는 시간, 실제 구글에서는 인터넷 속도에 따라 더 걸림) · 휴대폰 화면 가로 넘침 없음.

**대용량 파일** — 31MB 동영상·26MB PDF도 올라갑니다(예전엔 20MB 제한). 한 파일 1GB까지, 실제 한도는 이 컴퓨터 브라우저 저장 공간(보통 디스크 여유 공간의 상당 부분)입니다. ③단계 ‘저장 공간’에서 사용량을 보고 ‘🗜️ 사진 / 🎬 동영상 용량 줄이기’로 줄일 수 있습니다.

### 시안 고치기 · 추가하기

15종 모두 **같은 HTML 구조**(`.pf` → `.pf-cover`, `.pf-works > .pf-work` …)를 쓰고, 디자인은 CSS 테마(`.pf-t-<id>`)로만 다릅니다.

1. `src/data/sampleData.js`의 `DESIGN_TEMPLATES`에 `{ id, num, group, name, description, bestFor, colors }` 추가 (`group: "cute"`면 ‘귀여운 디자인’ 묶음)
2. `src/templates/portfolioRenderer.js`의 `getPortfolioTemplatesCss()`에 `.pf-t-<id> { ... }` 블록 추가
3. (선택) `src/style.css`에 디자인 고르기 미리보기 그림 `.tt-<id>` 추가
4. `npm run build:all`

휴대폰 화면은 `@container (max-width: 640px)` 규칙이 자동으로 한 줄 배치로 바꿉니다.

### 데이터 형식 (예전 백업 파일과 호환)

```js
{
  selectedTemplate, schoolLevel,
  profile: { studentName, schoolName, gradeClass, academicYear, portfolioTitle, subtitle, introText },
  works: [{
    id, entryType: 'subject' | 'project', subject, projectName, projectRole, linkedSubjects,
    semester, month, activityType, title, content, reflection,
    images: [{ id, name, caption, blob|dataUrl, width, height }],           // 🎨 작품 사진
    activityPhotos: [{ id, name, caption, blob|dataUrl, width, height }],   // 📸 활동 사진
    videos: [{ id, name, caption, size, mimeType, blob, width, height, duration,
               poster: { id, blob, width, height } }],                       // 🎬 동영상 + 썸네일
    attachments: [{ id, name, size, mimeType, blob|dataUrl,                  // 📄 PDF·파일
                    pages: [{ id, blob, width, height }], pageCount,         //    PDF 쪽 그림
                    docCols, docPages: [쪽 번호] }],                          //    보이기 배치·고른 쪽
    coverPhotoId,                                                            // 대표 사진·동영상
    photoLayout: 'auto' | '2' | '3' | '4'                                    // 사진 배치
  }],
  settings: { photoMaxSide: 1280 | 1600 | 2400 }                             // 새로 올릴 사진 화질
}
```

- 미디어 데이터는 `blob`(파일 그대로, 새 버전) 또는 `dataUrl`(예전 버전·예시 데이터) 중 하나에 들어 있고, 둘 다 읽습니다.
- 브라우저 저장소(IndexedDB `StudentPortfolioBuilderDB_v2`): `portfolioState`에는 가벼운 글 기록, `media`에는 `포트폴리오id/미디어id` 키로 파일을 저장합니다.

### 업데이트해도 자료가 사라지지 않게

- 저장소 이름·구조는 바꾸지 않고 **새 항목만 더하는 방식**으로 확장합니다. 예전 형식(사진 data URL, `currentPortfolio` 저장본, `.json` 백업)은 계속 읽습니다.
- 저장 형식을 바꿔야 할 때는 `store.js`의 `normalizeState`/`normalizeWork`에서 예전 값을 새 값으로 옮기세요(지우지 말 것).
- 확인한 것: 이전 배포본으로 만든 두 학생의 자료가, 같은 주소에 새 버전을 배포한 뒤에도 사진·글·설명·PDF·디자인까지 그대로 열리고, 저장소에 빠진 파일·남는 파일이 없음.
